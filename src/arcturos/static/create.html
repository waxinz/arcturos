Create & Run

Append-only store: creating adds rows; nothing is ever overwritten. Dispatches are synchronous — wait for the result message before re-submitting.

1 · Benchmark run — kick off

Runs a cold-cache sweep. Transport native targets a llama.cpp server (/completion); openai targets any OpenAI-compatible chat server (tabbyAPI, vLLM, litellm — needs a model name). Stores a run + one benchmark row per context target.

#ctxprefilldecode ttftwall

2 · Eval suite — create

Creates the suite record; populate results afterwards by replaying it (card 4).

3 · Eval suite items — define (optional, pre-store)

Suite JSON kept in the browser for dispatch: {"items":[{"id":"x","prompt":"…"}]} or multi-turn {"type":"multi-turn","id":"x","turns":[…]}.

4 · Eval replay — kick off

Replays the JSON from card 3 against an OpenAI-compatible chat endpoint, stores eval_results.

5 · Benchmark point — add manually

For external measurements: add one benchmark row to an existing run.

6 · Judgment — record

Blind A/B verdict between two stored eval results (see /judgments for ids).
